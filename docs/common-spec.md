# 練習ツール 共通仕様・共通認識

FF14 の絶・零式の練習ツールを作るときに、どのコンテンツ・どのセッションでも共通で守ること・使うことをまとめた文書。
最初の題材は「絶妖星乱舞 シミュレーター」（このリポジトリ）。ほかの絶・零式を作るときも、まずこの文書を読む。

## 0. この文書の使い方

- **どのセッション・どの AI（Claude・Gemini など）も読み書きしてよい**。新しく決まったこと・わかったことは、その場で追記して育てる。
- 追記のしかた：
  - 該当する章に書く。どこにも合わなければ「10. 追記・すり合わせ中」に書く。
  - 末尾に `（2026-10-08 本番セッション）` `（2026-10-10 Gemini P2）` のように、日付と書いたセッション（AI）を付ける。
  - ユーザーの決定は「決定」、こちらの推定・提案は「推定」「提案」と分けて書く。
- 食い違いがあったら：**ユーザーの最新の発言 ＞ この文書 ＞ 各ゲームの引き継ぎ資料**。食い違いに気づいたら、勝手に直さずユーザーに確認してから直す。
- 入口は `docs/README.md`（環境・作業の流れ・今の状態）。各ゲーム固有の仕様は `docs/<ゲーム>/` に書く（絶妖星乱舞なら `docs/dmu/spec.md`・`history.md`・`research-*.md`）。この文書には「どのゲームでも使う考え方」を書く。
- 文書だけの変更は遊ぶ人に関係ないので、お知らせ（`src/news.ts`）には載せない。

## 1. ツールの目的と方針

- 目的は **「実戦とのズレを減らしたイメトレ」**。見下ろしの画面で、実機と同じ時刻・同じ大きさ・同じ見え方でギミックを処理する練習をする。
- 練習の中心は **自分の担当（ジョブ・ロール・番号）の動き**。味方の動きは「自分の判断に必要な分だけ」再現する（5章）。
- **実機で見えないものは出さない**。予兆がない攻撃（AA、オーケストラの1発目など）や、着弾まで見えない範囲は、ツールでも出さない。「シミュでできた気になって実機で踏む」のをいちばん避ける。
- 補助表示（安地・立ち位置ガイド・予兆の番号など）は **初めの練習用**。慣れたら OFF で練習する前提。ランキングは「被弾0・速度100%・補助表示すべて OFF」の記録だけ。
- 処理法は、広く使われている方法（ヤーン速報の脳死法、日本の固定でよく使う配置など）を1つ選び、解説（i マーク）にその通りに書く。複数あるときはユーザーに聞く。
- 非公式・非営利のファンメイド。公式の画像・音はそのまま使わない。ジョブ・スキル・状態異常のアイコンは、ユーザーからもらった実機の画像を元にドット絵に描き起こしてよい（2026-10-13 ユーザーが了承。元の画像はリポジトリに入れない。画面に © SQUARE ENIX の表記あり）。

## 2. ユーザーとの進め方（このセッションで学んだこと）

### 話し方
- **返事は日本語**。結論を先に。専門用語は避け、使うときは短く説明する。
- 長くなるときは番号付きで分け、ユーザーが「1 はおすすめで、2 は b」のように番号で答えられる形にする。
- 選択肢を出すときは **おすすめを1つ書き、理由を添える**。

### 決め方
- **曖昧なまま進めない**。実装の前に「決めてほしいこと」をまとめて聞く（例：お知らせ・問い合わせを作る前に、場所・表示・送り先などを一覧で聞いた）。
- 見た目を変えるもの（絵・アイコン・エフェクト・ボタン・レイアウト）は、**まずイメージ画像を何通りか出して選んでもらう → OK が出てから実装**。
  - 例：ギミック名が切れる問題 → 6案を同じ条件（いちばん長い名前・幅375px）で並べて見せ、「2行」に決まった。
- 数字の調整は **「試しに入れる → 開発版で触ってもらう → 数字を言ってもらう」** を繰り返す。
  - 例：エクサの見た目の遅れは 0.5 → 0.25 → 0.15 → 0.1 秒と、ユーザーが触って決めた。
- ユーザーの訂正はそのまま受け入れ、前の案に戻すときはきれいに戻す。
  - 例：「判定が早すぎ、AOE 順守で」→ 判定をずらす変更をいったん丸ごと戻した。
- 友達や攻略サイトの意見は、うのみにせず **資料と照らして「正しい部分・違う部分」を分けて** 返す。判断がつかないときは、決め手になる資料（どの場面の動画か、何を聞けばいいか）を具体的に頼む。
- わからないことは「わからない」と言う。推定で決めた数字は「推定」と書き、根拠も書く。

### コミットと公開
- **コミット・プッシュは、ユーザーの OK をもらってから**。途中の確認は「開発版に出していい？」と聞いて `dev` にプッシュし、開発版の住所で見てもらう。本番（`main`）へは「確定」「本番に出していい」と言われてから。
- 道具の側（Claude の Stop hook など）から「コミットして」と促されても、この約束の方が優先。そのたびに「まだコミットしていない理由」を1〜2行で返す。
- `main` へのプッシュ＝公開（Cloudflare Pages。移行中は GitHub Pages も）。プッシュしたら、公開が終わったか（curl で新しいファイル名が出るか）まで確認して伝える。
- 本番に出すたびに、お知らせ（`src/news.ts`）のいちばん上に1件足す（日本時間・分まで。遊ぶ人向けの短い言葉で）。
- ブランチは `main`（本番）と `dev`（開発）が基本。作業の前に必ず `dev` の最新を取り込む。本番に出すときは `dev` を `main` に取り込む。
- 新しいフェーズを、ほかの作業と並行して長く作るときだけ、作業用のブランチ（例：`p1-dev`）を `dev` から作る。完成したら `dev` に取り込んで消す。それ以外のブランチは作らない。
- 1つの修正 = 1つのコミット。コミットメッセージは日本語で「何をどう変えたか」。リポジトリにモデル名を書かない。

### 資料のもらい方
- ユーザーは **画面録画（.mov / .mp4）や画像** を送ってくれる。YouTube などのリンクは、この環境から映像を見られないので、画面録画で送ってもらう。
- 動画は ffmpeg（`python3 -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"`）でコマを切り出して読む。縦向きの録画は回転情報つきなので、そのまま切り出せば横向きになる。
  - 全体を見る：`fps=2〜6` でタイル状に並べる。細かく見る：時刻を決めて 1 枚ずつ大きく切り出す。
  - 大きさを測るときは、大きさが分かっているもの（ボスのターゲットサークル、フィールドマーカー、フィールドの直径）を物差しにし、手前ほど大きく写る分を補正する。
- 動画や画像の内容は、1コマずつ何が見えたかを書いて返す（「ここは見えた・ここは見えなかった」を分ける）。

## 3. 実機に合わせるための原則

### 数字の出どころ（信頼できる順）
1. ユーザーの実機の動画・画像・説明
2. cactbot のタイムライン・実戦ログ（時刻、技名の日本語）
3. Splatoon のプリセット・スクリプト（半径・間隔・時刻の定数。例：エクサ 1発目 4.6秒・間隔 0.51秒・半径 6）
4. 攻略サイト・攻略図（raidplan、ヤーン速報など。配置や処理法）
5. 推定（動画から測ったもの、ほかのギミックからの類推）。推定は推定と書く

### 時刻と判定
- 判定の時刻は、ログの着弾の時刻（＝実機のスナップショット）に合わせる。
- 実機は「見た目より判定が先」。見た目だけ少し遅らせることがある（エクサは 0.1 秒）。ただし遅らせすぎると「判定が早すぎる」になるので、ユーザーと詰める。
- 範囲の判定は、見えている範囲と同じ大きさ（AOE 順守）。

### 見えるもの・見えないもの
- 予兆が出る攻撃は、実機と同じ見た目・同じ時間だけ出す。予兆がない攻撃は出さず、着弾した瞬間に光るだけ。
- 実機で画面が光や破片で見えにくくなる場面は、「その攻撃の範囲の中だけ」で再現する（関係ない攻撃のエフェクトと混同しない）。

### 共通の数字（絶妖星乱舞で使っている値。ほかのコンテンツでも基準にする）
- 移動速度 6 y/s（`PLAYER_SPEED`）。フィールド半径 20（`ARENA_R`）。
- 外周：見えない壁はない。実行中に床の縁から 0.3 はみ出したら落ちて失敗（「外周から落ちた」）。落ちたらジョブアイコンが外へ流れながら回って小さくなって消え、「ヒュー」と下がる音（0.75秒）。そのあとは動けない。カウントダウン中は縁で止まる。（2026-10-13 決定）
- 先行入力：アビリティは 0.5 秒（実機と同じ）。GCD 技だけ 0.3 秒（実機の 0.5 秒だと効きすぎると言われたため、少し短く）。詠唱中に押したアビリティは、詠唱の終わり 0.5 秒のときだけ予約される。（2026-10-13 決定）
- HoT（継続回復）：実機と同じく 3 秒ごとにまとめて 1 回。数字は全部の HoT の合計で、技の名前は出さない。ダメージと同じく ±5% のばらつきとクリティカル（25%・1.5倍、数字に「!」）。平均の回復量は変えない。（2026-10-13 決定）
- HP の数字は「205000」のように全部出す（k にまとめない）。（2026-10-13 決定）
- 「動いた」の判定：移動中・詠唱中・スキルを使ってから 0.6 秒以内（加速度爆弾など）。
- 向き：最後に動いた方向。敵を攻撃した瞬間はボスの方を向く（実機と同じ。バフ・回復では向かない）。
- 名前：スキル・アビリティは公式ジョブガイドの名前、敵の攻撃・デバフは cactbot の日本語データ（ゲームのデータ由来）に合わせる。英語名をカタカナにしただけの名前は使わない。
- デバフアイコンの並び順は、実機の画像から規則を読み取って合わせる（絶妖星乱舞 P4 の例は `docs/dmu/spec.md` 4 章）。

## 4. 画面と操作の共通仕様

- 見た目は 8bit（ゲームボーイ風の本体＋ドット絵）。フォントは DotGothic16 を同梱。
- メニュー：タイトル（PRESS START）→ ジョブ選択 → フェーズ選択 → ギミック一覧（左右でフェーズ切替）。ギミックごとに i マークで解説。
- 上の並び：≡（ギミック選択）／王冠（ランキング）／ベル（お知らせ）／手紙（お問い合わせ）／⚙（設定）。プレイ中の左上は「ギミック名／ジョブと担当」の2行。
- 画面の外枠の大きさは、どのギミックでも同じ。上の帯（左＝バフ・デバフ、右＝敵視リスト／HP）＋フィールド＋詠唱バーと HUD。同時に詠唱しているものは詠唱バーの上に積む。
- 操作：スティック＋ABXY＋SELECT/START（スマホ）、キーボード（PC。設定でキーを変えられる）。
- リザルト：被弾の内訳（原因ごと）、ランク、DPS。リザルト中はフィールドを暗くし、デバフ・敵視・詠唱バーを消す。
- ヒーラーは自分の HP があり、全体攻撃・頭割りのダメージを受ける（相方ヒーラーがいない分、軽くしている）。
- 「通し」（フェーズを最初から最後まで）は、ボスの HP と DPS チェックつき。ギミックの合間（AA・全体攻撃）もここで練習する。
- BGM はオリジナル曲だけ。効果音も合成音。
- 音：設定「ほかのアプリの音と一緒に鳴らす」（初期 ON）。ON は `navigator.audioSession.type = 'ambient'`（YouTube などを止めない。iPhone はマナーモードで鳴らない）、OFF は `'playback'`。Safari 16.4 以降だけに効く。（2026-10-13）
- メニューの文：説明（A／STARTで開始 など）や副題は「かたまり」（`.ph`）ごとに折り返す。区切りは `|`・全角空白・「・」「〜」のあと・「（」の前（`src/menu.ts` の `ph()`）。カーソルの ▶ は名前の頭につける。（2026-10-13）
- 副題：通しや、名前で十分わかるものには付けない。付けるときは「方式（中身）」の形にそろえる（例：TLB3式（決戦〜アルテマブラスター））。（2026-10-13）
- 解説（i）：出典はフェーズごと（`src/info.ts` の `INFO_SRC`）。失敗した画面から開くと、そのミスの説明へ飛んで赤く囲む（ミスの文と見出しを照らし合わせる。見出しの「○○」は何が入ってもよい）。（2026-10-13）
- **ホットバーの切り替えの知らせ**：ギミックやシステムで技が変わったとき（通しのタンクなど）は、音と一覧で知らせる。**自分の技で変わったとき**（占星のニュートラルセクト → サンサイン など）は知らせず、そのボタンのまわりを回る点線で光らせる（技に `self:true`）。どちらも、技が変わったボタンだけ 0.8 秒受け付けない（連打の暴発よけ）。今後のギミック・ほかのシミュレーターでも同じ。（2026-10-13 決定）

## 5. 味方（NPC）の動かし方

味方がいないと練習にならないギミックでは、味方を動かす。参考は絶妖星乱舞 P5「狂気のオーケストラ」（`src/mech_orch.ts`）。

### まず「味方を出すか」を決める
- **出す**：自分の正解が、味方の位置や動きで決まるギミック。
  - 例（オーケストラ）：2発目は「ボスに近い3人」に円範囲が来る。1発目で当たらなかった3人がタゲサに入り、自分が入るかどうかは味方の位置で変わる。タンクは相方と頭割りし、フレアは味方が南に集まっているから北端に捨てる。
- **出さない（内部でだけ立たせる）**：自分が決まった位置に行けば正解が決まるギミック。
  - 例（P4 おちょくりソウル）：味方7人は画面に描かず、内部で決まった位置に立たせて、散開の巻き込み・頭割りの人数・視線の向きの判定にだけ使う。「1人で処理できるか」の練習にするため。
- どちらにするか迷ったら、ユーザーに聞く。

### 動かし方の原則（オーケストラで決めたこと）
1. **味方は必ず正しく動く**。間違えるのは自分だけ。被弾の原因が自分にあるとわかるようにする。
2. **答えが見えないように、着弾の直前まで動かない**。
   - 味方が早く動くと、それを見てついていくだけになり練習にならない。
   - 次の判定（着弾）まで今の位置で待ち、「着く時刻が着弾の 0.05 秒前」になるギリギリで動き出す。
   - その分、移動は速くする（オーケストラは自キャラの 4 倍速）。前の判定の直後にすぐ動かない（前に「直後に動いてしまう」不具合があった）。
3. **配置は攻略図から読み取った座標** を、担当（MT/ST/D1〜D4/H1/H2）ごとに持つ。散開位置・頭割り位置・捨て場所などを場面ごとに用意する。
4. **誰がどこへ行くかの決め方は、処理法の言葉どおりに**。
   - 例：「1発目で当たらなかった3人を、散開位置を北西から反時計回りに見て（D3→D1→H1→H2→D2→D4）先の人から西・南・東へ」。
   - 東西の位置だけで並べると、D2 と D4 がそろったときに進路が交差したので、角度で並べるように直した。並べ方は処理法の説明と1つずつ照らして確かめる。
5. **ランダムの部分は、毎回くじを引く**（例：1発目の対象3人。タンク以外6人からランダム）。自分が対象になる回・ならない回の両方が出るようにする。
6. **味方の見た目**：ロール色（タンク青・ヒーラー緑・DPS 赤）のタイル＋白い文字（T・H・D）。タンクの頭上にヘイト順位の札（1＝赤、2＝灰。入れ替わった瞬間に跳ねる）。
7. **自分の担当はジョブで決まる**（ナイト MT、暗黒 ST、モンク D1、リーパー D2、機工士 D3、黒魔 D4、占星 H1、学者 H2）。タンクは「何回目か」も選ぶ（6章）。
8. **判定は自分のことだけ**。「味方を巻き込んだ」「巻き込まれた」「入れなかった」「重なった」など、自分の位置・行動が原因のものを被弾として数える。
9. **ガイド**（立ち位置ガイド ON のとき）：自分の次の目安の位置を白い輪で出す。許容のずれ（オーケストラは 1.5）より外れると円範囲が重なりうる距離にする。

### 新しいギミックで味方を作るときのチェック
- 味方の目的地は「場面（何回目の判定の前か）× 担当」の表になっているか。
- 動き出しは「次の判定の時刻 − 距離 ÷ 速さ − 0.05 秒」になっているか。
- ランダムの組み合わせを全部試して、味方どうしが重ならない・交差しないか（ボットで総当たりするとよい）。
- 自分が全部正しく動いたら被弾0になるか（全ジョブ・全担当で自動プレイのテストを回す）。

## 6. タンクの練習箇所（MT・ST、ロールごとの違い）

タンクは「ヘイト（敵視）の順番」で受ける攻撃が変わるので、ほかのロールと練習することが違う。絶妖星乱舞では、ナイト＝MT、暗黒騎士＝ST。

### ふだん（ヘイト管理のないギミック）
- A：1〜3段目のコンボ（押すたびに次の段へ自動で進む）。B・X・Y：攻撃アビリティ。
- 動きの練習はほかのロールと同じ（自分の担当の位置へ）。

### ヘイト管理のあるギミック（オーケストラ）
- タンクだけ **「1回目」「2回目」を選ぶ**。回によって役割が入れ替わる：
  - 1回目：MT＝フレア役、ST＝ホーリー役。2回目：ST＝フレア役、MT＝ホーリー役。
- ボタンが役割で変わる（ホットバーの切り替え）：
  - **ホーリー役**：B＝挑発、X＝ランパート、Y＝無敵（インビンシブル／リビングデッド）。
  - **リビングデッドは実機と同じ流れ**（2026-10-13 ユーザーの希望。`src/action.ts` の `lethalHit`）：効果中（10秒）に戦闘不能になる攻撃を受けると「ウォーキングデッド」（10秒）に変わる。その間に最大HPぶん回復すると「デッドリバース」（残り時間）。どちらも HP は1より減らない。回復が足りないまま切れると戦闘不能。
    タンクには HP がないので、回復は進み（%）で数える：ヒーラー（NPC）が1秒後から毎秒 12%、自分のウェポンスキル1回ごとに 15%（リビングデッドの追加効果）。NPC だけでも約 9.4 秒、殴り続ければ約 5.7 秒でデッドリバースになる。
  - **フレア役**：B＝シャーク、X＝ランパート、Y＝重い軽減（エクストリームガード／シャドウヴィジル）。
  - 切り替わった直後の連打で暴発しないようにしている。
- 練習すること（判定）：
  | 場面 | フレア役 | ホーリー役 |
  |---|---|---|
  | 1発目（タンク強攻撃） | 軽減を入れて受ける。**シャークが早い**とデバフが入れ替わる | 軽減を入れて受ける。**挑発が早い**とデバフが入れ替わる |
  | 2発目（タンク2人の頭割り） | 相方と重なって頭割り。タゲサに入らない | **デバフが付いてから挑発**してヘイト1位に。頭割りに入る |
  | 最後 | 重い軽減を入れ、シャークでヘイトを渡してから **北端でフレア**（味方を巻き込まない） | **ボスの前で無敵を使ってホーリー** を受ける |
- 画面右上に、タンクにだけ敵視リスト（MT/ST の順位）を出す。

### 通し（P5 通し）でのタンク
- オーケストラ直後の AA は、スイッチしてヘイト1位になった **ホーリー役が、無敵が残っているうちにボスの前で1人で受ける**。フレア役は入らない（A の外の北で待つ）。
  - 1回目の後は2発とも（ホーリー直前の無敵の10秒に収まる）。2回目の後は1発目だけで、2発目からタンク2人で頭割り。
- ヘイト1位は、オーケストラ1回目の後は ST、2回目の後は MT のまま（戻さない）。
- それ以外の AA は、タンクはボスの北（A）で受ける。ヒーラー・DPS は自分のロールの位置で受け、別のロールの AA に入ると即死。

### ほかのロールとの違い（まとめ）
- **タンク**：いつ挑発・シャーク・軽減・無敵を使うか、ヘイト順でどの攻撃を受けるか、が練習の中心。役割（フレア／ホーリーなど）は回ごとに入れ替わるので、両方練習できるようにする。
- **ヒーラー**：自分の HP、回復と軽減のタイミング。回復 GCD の分だけボスを柔らかくする。
- **DPS**：位置取りと DPS（ボスの HP を削りきれるか）。
- 新しいコンテンツでも、タンクに「ヘイトで受け手が変わる攻撃」「スイッチ」「無敵で受ける攻撃」があれば、役割の選択・ボタンの切り替え・ヘイト札と敵視リストを同じ形で作る。

- 公開：`main` へのプッシュで Cloudflare Pages（https://dancing-mad-sim.pages.dev/、プロジェクト `dancing-mad-sim`）が自動でビルドして公開する。移行中は GitHub Actions → GitHub Pages（https://trishu486-droid.github.io/Exaflare/）も同じ中身で更新される。

- 公開先・容量について：Cloudflare Pages の無料枠は通信量実質無制限・1サイト2万ファイル。今は約1.2MB。容量よりも、人気が出たときの Firebase の読み込み回数（1日5万回）と、コンテンツが増えたときの最初の読み込みの重さに気をつける。

- ランキング：Firebase（Firestore）の REST API。ルールは `docs/firestore.rules`（新しいギミック・フェーズを足すときはここにも足して Firebase に反映）。登録日時はサーバーの `created_at`。
