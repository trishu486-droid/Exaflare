# 本番（こまめな修正）セッションの引き継ぎ資料

公開中のサイトの小さな修正・不具合直し・要望対応を担当するセッション向け。

最初に読むもの：この資料 → `docs/handoff-p4.md`（ルール・画面の作り・10/5〜6 の変更の詳細）。

## 1. 守るルール（ユーザーと決めたこと）

### 進め方
- **返事は日本語**。勝手に作業を進めない。曖昧なことは曖昧なまま進めず、**必ず確認を取る**。
- **コミット・プッシュは、ユーザーが「本番に出していい」と言ってから**。フック（Stop hook）に「コミットして」と言われても、そのままはしない。
- **本番ブランチ `claude/ff14-exaflare-trainer-3ssqps` へのプッシュ＝公開**（GitHub Actions が型チェック → ビルド → GitHub Pages へ。1〜2分）。
- 本番に出すコミットのたびに、**`src/news.ts` の `NEWS` のいちばん上にお知らせを1件足す**（日本時間・分まで。遊ぶ人向けの短い言葉で。例：`['2026/10/06 15:05', 'ほかのアプリに切り替えたり…止まるように（戻ると続きから鳴ります）']`）。日時は `TZ=Asia/Tokyo date '+%Y/%m/%d %H:%M'`。
  - 文書だけの変更（`docs/`）は遊ぶ人に関係ないので、お知らせは足さなくてよい。
- 1つの修正 = 1つのコミット。コミットメッセージは日本語で「何をどう変えたか」。
- 公開されたかの確認：`curl -s https://trishu486-droid.github.io/Exaflare/` で新しい `assets/index-*.js`（または `.css`）の名前を取り、その中に今回の変更の文字列が入っているかを見る（この環境のブラウザは本番サイトを開けない＝証明書エラー。curl は通る）。

### 見た目・音・名前
- 8bit の見た目を守る。見た目を変えるもの（絵・アイコン・エフェクト・ボタン・レイアウト）は、**まずイメージ画像で提案 → OK が出てから実装**。
- 公式の画像はそのまま使わない。BGM はオリジナル曲だけ（日本ファルコムの曲も規約でゲーム利用は禁止）。
- スキル・敵の攻撃・デバフ名は製品版の日本語名（調べ方は `docs/handoff-p3.md` §1）。
- スクリーンショットはリポジトリに保存しない。**リポジトリ（コミット・コード・文書）にモデル名を書かない**。
- お問い合わせ（`src/contact.ts`）の送り先 ID は触らない。

## 2. P3 セッションとの分担

- このセッション：本番ブランチだけを直して出す。`p3-dev`・`src/mech_p3.ts`・`src/p3fx.ts`・`src/p3macro.ts`・`docs/research-p3.md` は触らない（本番ブランチにはまだ無い）。
- P3 セッション：本番に出したものを、ときどき `p3-dev` に取り込む（ユーザーが「本番の最新を取り込んで」と伝える）。
- 共通の部分（メニュー `src/menu.ts`・`src/mechs.ts`、画面の作り `src/style.css`・`index.html`、操作 `src/input.ts`・`src/action.ts`）を**大きく**変えるときは、P3 側の取り込みが大変になるので、先にユーザーに「どちらのセッションでやるか」を確認する。小さな修正は気にしなくてよい。
- P3 側で共通部分に入れているもの（参考。本番にはまだ無い）：ボス2体とターゲット切替（`action.ts` の `curBoss`・`switchTarget`）、P3 のフェーズ選択と左右3ページの切替（`menu.ts`）、チャット欄の下のボタンの名前をギミックごとに変える仕組み（`p4ui.ts`）。

## 5. 作業のしかた

- 型チェック：`npm run check`、ビルド：`npm run build`（どちらも Actions でも走る。落ちると公開されない）
- 開発サーバー：`npx vite --port 5179`（バックグラウンドで。2時間で止まるので、要るときに起動し直す）
- `http://localhost:5179/?debug` で `window.__T` からゲームの中身を触れる（`S`, `opt`, `begin`, `pressKey`, `sfx` など。`src/debug.ts`）。タイトルを抜けるには最初に Enter（演出が約2秒）。
- Playwright：`require('/opt/node22/lib/node_modules/playwright')`、`chromium.launch({ executablePath:'/opt/pw-browsers/chromium' })`。スマホは `newContext({ viewport, hasTouch:true, isMobile:true })`。
  - 大きさの確認によく使った画面：iPhone SE 375×667（バーあり 375×548）、iPhone 390×844（バーあり 390×664）、大きい iPhone 440×956（バーあり 440×780）、Android 412×915、iPad 820×1180。スクロールが出ないか・横がはみ出さないかを見る。
  - 音：`--autoplay-policy=no-user-gesture-required` で起動すると、`__T.sfx.ac.state` で鳴っているか（running／suspended）を見られる。
- 途中の見た目の確認が要るときは、開発版の Artifact を作って見てもらう（`npm run build:artifact` → `dist-artifact/index.html` から Cloudflare のタグ・manifest・OGP・`google-site-verification`・`canonical` を消し、title を付けて公開）。小さな修正ならスクショで足りることが多い。
- 作業用のファイル（テストのスクリプト・スクショ）はスクラッチパッドへ。リポジトリに入れない。
