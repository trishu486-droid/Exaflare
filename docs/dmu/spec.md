# 絶妖星乱舞 シミュレーター 仕様

絶妖星乱舞（絶ケフカ）の練習ツールで決まっている仕様をまとめた資料。どのコンテンツにも共通の決まりは `docs/common-spec.md`、経緯は `docs/dmu/history.md`。

## 1. 名前・メニュー・画面

### 名前
- 「絶妖星乱舞 シミュレーター」（タイトル画面は「絶妖星乱舞 SIMULATOR」）。検索向けの説明文には「絶妖精乱舞」「シュミレーター」も残す。フェーズ名（P3・P4・P5）やギミック名は説明文・タイトルに入れない（ユーザーの決定。フェーズが増えても直さなくて済むように）。
- スキル・アビリティ・敵の攻撃・デバフは**製品版の日本語名**。英語名をカタカナにしただけの名前は使わない（例：×エッジ・オブ・シャドウ → ○漆黒の剣）。
  - ジョブの技：公式ジョブガイド https://jp.finalfantasyxiv.com/jobguide/ （レベル100で確認済み）
  - 敵の攻撃名：cactbot の日本語データ `ui/raidboss/data/07-dt/ultimate/dancing_mad.ts` の `'locale': 'ja'` の `replaceText`（時刻は同じフォルダの `dancing_mad.txt`）
  - デバフ名：ゲームのステータスデータ（xivapi の日本語データ）。なければ日本語の攻略記事。海外のまとめ記事の訳は使わない。

### メニュー
- タイトル（PRESS START）→ ケフカの顔がうっすら出て高笑い（`src/kefka_intro.ts`、約1.9秒。もう一度押すと飛ばせる。効果音オフなら鳴らない）→ ジョブ選択 → フェーズ選択（P3／P4／P5／おまけ）→ ギミック一覧 → 担当の選択など → 開始。
- ギミック一覧は左右でフェーズを切り替え。前に選んだフェーズは `opt.phase` に保存。
- フェーズ選択のボタンの下の文字は「その敵の一般的な呼び名」（P3＝エクスデス＆カオス、P4＝ネオエクスデス＆カオス、P5＝カオスケフカ）。
- P3・P5 は一覧のいちばん下に「通し」（P3 通し・P5 通し）。P4 は「P4 通し」（おちょくりソウル）の1つだけ。P5 通しは以前は隠しコマンドだったが、今は常に出す。
- ギミックごとに i マークで解説（`src/info.ts`）。リザルトでは Y で解説。
- ジョブは8つ：ナイト(MT)・暗黒騎士(ST)・モンク(D1)・リーパー(D2)・機工士(D3)・黒魔道士(D4)・占星術師(H1)・学者(H2)。技は `src/jobs.ts`。

### 上の並びと左上の表示
- ≡（ギミック選択へ）／王冠（ランキング）／ベル（お知らせ）／手紙（お問い合わせ）／⚙（設定）。いつも表示。
- プレイ中の左上は2行（1行目ギミック名、2行目ジョブと担当、13px）。オーケストラだけ「狂気の」を省いて「オーケストラ」。幅 359px 以下では上のボタンを細くする。

### 画面の配置
- 画面の外枠の大きさは、どのフェーズでも同じ。
- P5 型：上の帯（左＝バフ・デバフ、右＝敵視／HP）＋横いっぱいのフィールド＋下に詠唱バーと HUD。チャット欄なし。
- P4 型（`.gb.p4on`）：上の帯＋フィールド（上下の星空を切って大きく）＋詠唱バーと HUD＋チャット欄（左7割＝PT マクロ、右3割＝自分のメモ）。P3 もマクロ欄を使う。
- 同時に詠唱しているものは、詠唱バーの上に積む。
- ボタン（チャット欄の下の4つ）の名前はギミックごと（`buttons`）。使わないボタンは灰色。P4＝早 散開／遅 散開／止まる／動く（PC は 5〜8 キー）。P3＝ターゲット切替／（タンク前半）LB3・攻撃／バインド／禁止。
- 結果画面：デバフ・敵視・詠唱バーを消し、フィールドを暗くする。被弾の内訳・ランク・DPS。P4 の結果は枠の中でスクロール。
- スマホ：本体を画面の高さにちょうど収まる大きさにする（`src/fit.ts` が二分探索で測る。下限 225px・上限 640px）。ホーム画面から開いたときは `html.app` で上の余白を「時計の表示の高さ＋22px」に。横向きはゲームボーイアドバンス風（左にスティック・右にボタン）。
- ページが見えなくなったら BGM と効果音を止める（戻ると続きから）。
- 大きな攻撃の光・被弾の赤い光は、画面全体に出す。

## 2. 共通の機能

- **お知らせ**（`src/news.ts`、ベル）：日時（日本時間・分まで）と内容を新しい順に全部。未読はベルの赤い点と NEW（端末の `newsSeen` に、最後に見たいちばん新しい日時を保存）。**本番に出すたびにいちばん上に1件足す**（遊ぶ人向けの短い言葉で。日時は `TZ=Asia/Tokyo date '+%Y/%m/%d %H:%M'`）。
- **お問い合わせ**（`src/contact.ts`、手紙）：ニックネーム（任意・12文字）と本文（1000文字）だけ。Google フォーム「絶ケフカシミュ問い合わせ」（ユーザーの Google アカウント）へ `no-cors` で送る。ジョブ・フェーズ・ギミック・端末・画面サイズ・ホーム画面か・版（お知らせの最新日時）・UA を自動で添える。返信はしない。送り先の ID（`entry.312787377` ニックネーム、`entry.16255419` 本文、`entry.613677479` 自動情報）は触らない。
- **ランキング**（`src/ranking.ts`、王冠）：Firestore の REST API。DPS 順・Perf（同じギミック・同じジョブの中での位置）・登録日（月/日。押すと分まで。サーバーの `created_at`）。被弾0・速度100%・補助表示なしの記録だけ登録できる。
  - 対象は P5 だけ。P3・P4 は「対象外」（数字を実機に寄せきってから入れる）。入れるときは `docs/firestore.rules` の `d.mech in [...]` に足して Firebase に反映し、`rankBlock()` の対象外の行を消す（P3 は `p3a`, `p3c`, `p3d`, `p3`）。
  - Firebase の無料枠は読み込み1日5万回。人気が出たら Perf の計算をまとめるなどで減らす。
- **設定**（⚙）：基本・表示・ギミック・サウンド・キー（PC のみ）・情報のタブ。情報タブに「非公式・非営利。スクウェア・エニックスとは無関係」「BGM はオリジナル」「Cloudflare Web Analytics（Cookie なし）」を書いている。
- **BGM**：すべてオリジナル曲（`src/audio.ts`・`src/bgm_*.ts`）。P4 は「紅き疾走」（`src/bgm_rush.ts`、ホ短調・BPM176・約38秒ループ）で、P4 のときは自動でこの曲。候補だった「混沌への決戦」（`src/bgm_p4.ts`）も一覧に残している。既存の曲のメロディは使わない（日本ファルコムの曲は規約でゲーム利用が禁止）。
- **ホーム画面に追加**（PWA）：`public/sw.js`。公開先（`pages.dev`・移行中は `github.io`）でだけ登録する（`src/pwa.ts`）。

## 2.5 P2（ゴッドケフカ）※開発中（`p2-dev`）

- 調査は `docs/dmu/research-p2.md`。区切りは「ミッシング」「トライン」（P2 通しは後で）。ランキングの対象外。
- 見た目（2026-10-09 ユーザーが絵で OK）：ゴッドケフカのドット絵は描かず、赤いターゲットサークル（半径7）だけ。外側は赤白のうず、床は暗い網目。裁きの光のあとは床も外側も金色。
- アイコン（`src/p2icons.ts`）：スペルハザード（P4 と同じ盾の形・金茶色・右上に残りの数）、頭上の予兆（扇＝オレンジの扇・要が下、円＝とげのある金の丸、頭割り＝上下左右の金の山形がまん中を向く）。
- 画面：味方7人は出すが、パーティリストは出さない。左上に自分のデバフ（スペルハザード・被魔法ダメージ増加）。ヒーラーは右上に自分の HP。
- **ミッシング**（`src/mech_p2m.ts`）：終末の双腕 → ミッシング → 塔8回（未来／過去の終焉4回・消滅の脚4回）→ 裁きの光。処理法はヤーンの優先順＋立ち位置ぴれん（南調整は後で）。
  - 塔は毎回 45 度ずれる（最初の向きと時計回り・反時計回りは毎回くじ）。立ち位置は「塔のある側を南」とみなした相対の座標で持ち、塔の向きに回して使う。
  - 大きさ（推定）：塔 半径4（中心はケフカから 8.5、塔の側の左右 45 度）、頭割り・円 半径5、扇 90 度・長さ16、未来過去の円 半径5、分身はケフカから 3.2。消滅の脚は半面（未来＝前、過去＝後ろ）。分身とケフカは詠唱の始まりにランダムな人の方を向く。
  - 味方は着く時刻がギリギリになるように動く（`common-spec.md` 5 章）。全担当で自動プレイの被弾0、塔・頭割り・円・扇・消滅の脚を全パターン（くじ 600 通り）で確かめた。
  - タンクの終末の双腕は「タンク2人で重なる」だけを判定（P2 のタンクのボタンにはまだ軽減がない）。
  - 2026-10-10：ターゲットサークルは P5 と同じピンクの塗りつぶし（半径8）に変更。背景のうずはミッシングの詠唱完了から（それまで星空）、画面全体（`screenBg`）。味方のタイルに担当（MT など）。ミッシング前はペアで少し離れて立つ。
- **トライン**（`src/mech_p2t.ts`）：裁きの光 → トライン（3・1・3）→ 破壊の翼（半面）→ 破壊の翼（近い人・遠い人）→ 終末の双腕。三角は一辺10・東西向き、頂点の爆発 半径6（`research-p2.md` 3.1）。爆発の範囲は事前に出さない。組み合わせは cactbot の4パターン。安地はヤーン（ヒーラー・DPS 南 → 東、タンク 北 → 西で1回目の三角）。半面は全員同じ所でよけ、1回目の三角のすぐ外で待って、爆発したら中へ。MT・ST の位置は、2・3回目の円が来ない所を毎回計算。くじ 2000 通りで被弾0を確認。
- ミッシング（2026-10-10）：ミッシングだけの練習は、ミッシングの詠唱の1秒前から始め、最初から整列している（最初の終末の双腕は通しのときだけ。`p.withEmb`）。ミッシング前の散開は中央より少し南に縦2・横4（上 MT ST D1 D2、下 H1 H2 D3 D4。ペアは縦）。
- 背景（2026-10-10）：ステージはいつもの暗い床のまま。外側の背景は、ミッシング前と裁きの光のあとは金色、そのあいだは赤白のうず。
- 開発版の住所では、上の並びの左に「開発」の札（`src/devbadge.ts`）。

## 3. P3（エクスデス＆カオス）

詳しい仕様・数字・処理法は `docs/dmu/research-p3.md`（決定事項の表と 9 章のヤーンの処理）。

- ギミック一覧：前半（バウル・オブ・アゴニー＋アルテマブラスター）・じしん＆ブラックホール・どんどこ地団駄・P3 通し。
- 処理法はヤーン（前半は TLB3 式、後半は頭上マーカー式）。
- タンク強攻撃（サンダガ）は「対象の人を中心にした円範囲」。
- ボスを殴れない時間は「INVULNERABLE」と出し、ダメージなし・コンボも進まない。
- 回復で処理するギミックでは、ヒーラーにだけ8人の HP をフィールドの右上に出す（判断に要るデバフ＝土・泥土・土属性耐性低下［強］だけ HP バーの上に）。
- 回復の速さで進むギミック（泥土の揺れ）は、実機の時刻ではなくプレイヤーの回復の速さに合わせる。
- 通しは、ボスを殴れるようになったところからカウントダウン5秒。HP を削りきってもビッグバンの後まではクリアにしない（`killAfter`）。間に合わなければ時間切れの技名（`enrageName`）。
- AA は入れていない（ユーザーの決定）。

## 4. P4（おちょくりソウル）

詳しい調査は `docs/dmu/research-p4.md`。

- 味方7人は画面に出さない（内部では決まった位置に立ち、判定にだけ使う。「1人で処理できるか」の練習）。
- 散開：自分の側（1セット目はネオエクスデスの方向が北、2セット目は真北。タンヒラ西・DPS 東）にいて、誰も巻き込まなければ正解。半径6。
- 頭割り：自分の組の頭割りの人から6以内、散開に巻き込まれない。
- 視線：視線持ちはケフカのターゲットサークル（半径8）の中、ほかは外。本当ならケフカを見ない、嘘なら見る（正面±45°）。向きは足元の輪の黄色い三角。向きは最後に動いた方向で、敵を攻撃した瞬間はケフカの方を向く（バフ・回復では向かない）。
- 加速度：爆発の瞬間に「移動・詠唱中・スキル使用から0.6秒以内」なら動いた扱い（`isActing()`）。ミスしたときだけ打ち上がる演出。
- 事前に見えるもの：なぞなぞマジック等の予兆、ケフカの輪の玉（上の紫＝サンダガ、下の青＝ブリザガ）、無の氾濫はネオエクスデスの位置と左右の目印（紫＝ピンクの六角形の泡、青＝白い氷の逆三角の泡）だけ。色の地帯・生死の境界・混沌の炎／水の範囲は着弾まで見せない。
- ボスは中心から17。おちょくりソウルは詠唱バーだけ（演出なし）、約10秒でボスが出る。
- デバフの並び（実機の画像から）：傷 → フィールド／超越 → 呪詛 → フォーク／水圧縮 → 加速度 → 炎と水（炎と水の順は毎回ランダム）。
- メモのボタン（早 散開／遅 散開／止まる／動く）。押したメモはチャット欄の右に流れる。リザルトでメモの答え合わせはしない。

## 5. P5（カオスケフカ）

詳しい調査（エクサ）は `docs/dmu/research-p5-exa.md`。

- **混沌の終末（エクサ）**（`src/mech_exa.ts`）：時刻・半径は Splatoon のスクリプトの定数と同じ（1発目4.6秒、間隔0.51秒、セット2.5秒、半径6）。判定は着弾の時刻。着弾した床（溶岩の円、ひび入り）を同じ大きさで 0.9 秒残す（`LAVA`）。着弾の光（`FLASH`）と床の破片あり。画面全体の光は足さない。爆発の見た目だけ 0.1 秒遅らせる（`VIS_DELAY`。実機は「見た目より先に判定」）。
- **ミッシング**（`src/mech_miss.ts`）：1回目 中央＋斜めX → 2回目 Xの反対側＋Xから反時計回り90°の斜め → 3回目 残りの斜め＋東西南北（北は出さない）→ 4回目 残りの東西南北から2つ。処理はヤーンの脳死法で、2 → 3 → 4 → 1 → 2 と4回目まで時計回り（反時計回りの例外なし）。
- **狂気のオーケストラ**（`src/mech_orch.ts`）：味方7人を出す（動かし方は `common-spec.md` 5 章）。タンクは1回目／2回目を選び、フレア役・ホーリー役が入れ替わる（`common-spec.md` 6 章）。フレアは半径25。
- **フラッド**（`src/mech_flood.ts`）、**スリースターズ**（`src/mech_celes.ts`）。
- **P5 通し**（`src/mech_run.ts`）：ターゲット可能から 3 カウントで開始、ミッシング・ゼロ（時間切れ）まで約3分40秒。ギミックの合間に連続アルテマ・AA・混沌の渦。
  - AA（魔撃）：タンク＝A（ボスの北、半径3）、ヒーラー＝4（南西、半径4）、DPS＝3（南東、半径4）。予兆なし。2つ受けると即死。オーケストラ直後の AA はホーリー役が無敵で1人で受ける（1回目の後は2発とも、2回目の後は1発目だけ）。
  - 混沌の渦：半径4（Splatoon では5。そろえるかは未決）。
  - ボスの HP は目標 DPS の95%を出し続けて削りきれる量。ヒーラーは回復 GCD の分を引く。

## 6. ギミックの作り方（共通の形）

ギミックは `src/mech_*.ts` に1つずつ。`mech_exa.ts`（短い）と `mech_p4.ts`（通し・大きい）を手本にする。

```ts
const X = (() => ({
  id:'…', name:'…', sub:'…', view:24, start:{ x:0, z:4 }, slots:true, // slots：担当（MT/ST など）を選ぶか
  gen(){ /* 毎回ランダムなパターンを作って返す */ },
  create(pattern){
    return {
      end: 120,                               // 終わりの時刻（秒）
      casts: [{ name:'…', start:0, len:5 }],  // 詠唱バー（製品版の名前）
      progress: t => '…',                     // 上の段に出す進行表示
      tick(t){ /* 判定。当たったら hurt('理由') */ },
      draw(t){ /* フィールドに描く（gfx.ts の px(), ring(), disc() など） */ },
      // 必要なら：drawFloor, safe/safeActive, guide, status, enmity, tankRole, bossHp/hpGate, intro, countdown, t0,
      //           activeTime, resultExtra, chat/say, buttons, killAfter, enrageName
    };
  },
}))();
```

- 座標：フィールドの中心が (0,0)、半径 20。北が z マイナス。`px(x)` で画面のドットに。
- 被弾：`hurt('理由')`（`gfx.ts`）。ヒーラーへのダメージ：`healerHit(ダメージ, '攻撃名')`（`action.ts`）。
- 新しいフェーズを足すときは `src/mechs.ts`（ギミック一覧・`phaseOf`・`menuMechs`）と `src/menu.ts`（`PHASES`・左右の切り替え）に足す。

## 8. テストのしかた

- 型チェック：`npm run check`、ビルド：`npm run build`（`main` へのプッシュでも Actions で走る。落ちると公開されない）。
- 開発サーバー：`npx vite --port 5179`（バックグラウンドで。時間が来ると止まるので、要るときに起動し直す）。
- `http://localhost:5179/?debug` で `window.__T`（`S`, `opt`, `begin`, `pressKey`, `job`, `sfx`, `BGM_TRACKS` など）。
  - 例：`__T.opt.mech='p3'; __T.opt.job='rpr'; __T.begin();`。`window.__noHurt=1` でミスを数えない。タイトルを抜けるには最初に Enter（演出が約2秒）。
- Playwright：`require('/opt/node22/lib/node_modules/playwright')`、`chromium.launch({ executablePath:'/opt/pw-browsers/chromium' })`。スマホは `newContext({ viewport, hasTouch:true, isMobile:true })`。外部通信は `ignoreHTTPSErrors:true`、ランキングは `page.route` で偽のデータを返す。
  - よく使う画面：iPhone SE 375×667（バーあり 375×548）、iPhone 390×844（バーあり 390×664）、大きい iPhone 440×956、Android 412×915、iPad 820×1180。
  - 音：`--autoplay-policy=no-user-gesture-required` で `__T.sfx.ac.state` を見る。`OfflineAudioContext` に書き出して WAV にし、ユーザーに聴いてもらう。
- 全ジョブ・全担当で「正しく動けば被弾0」になる自動プレイを回す。
- 作業用のファイル（テストのスクリプト・スクショ・動画のコマ）はスクラッチパッドへ。リポジトリに入れない。
